# OpenSprite 三动作统一 tracker：执行计划

更新：2026-10-31。用户已纠正为**一个 tracker、一个共享策略同时支持三条动作**。最初“三个独立策略”的理解作废。

## 交付范围

本仓库独立包含 OpenSprite 机器人资产与参数、从 OrangeDuck LAFAN BVH 到 OpenSprite 的 retarget、三动作训练库、最新 X2 SuperMimic 的本地移植、训练/恢复/评估入口和交付说明。`.reference/` 保存调研快照、论文和源数据材料，运行程序不得依赖它或其他仓库。训练目标为仿真 tracker；不包含真机部署。

## 团队与交叉质询

机器人成员核实官方 URDF/MJCF、动力学、碰撞和 31 个关节；retarget 成员核实历史测试动作、原始 BVH 时间轴、坐标和 IK；tracker 成员核实最新分支、世界模型、训练与恢复。主代理集成、检查独立性、分配训练预算和每小时复核。各成员审查相邻接口，发现问题写入本目录的研究记录与复核记录。

必须回答：是否把 X2 关节/扭矩/脚尺寸带入了 OpenSprite？躺倒时的模型轴和参考重力是否正确？脚或手与地面接触是否合理？原始 BVH 是否有每关节平移通道？训练动作边界是否泄漏？世界模型能否通过 actor 输入反传且冻结参数？恢复是否保存优化器和时钟？长动作是否只展示成功片段？

## 已补全的信息

- 官方入口：https://github.com/BeijingDynamics/open_sprite 。Sprite0825 大约 0.95 m、31 个驱动关节；实际为腿 12、腰 2、双臂 14、头 3，不能按 X2 的相同自由度数量推断相同关节。
- 本机参考项目：`yy-retargeter`、`x2-general-tracker`、`beyondmimic-umr`。仅用于调研/复制，不进入运行依赖。
- 原始数据：OrangeDuck `lafan1-resolved`，本机存在完整 BVH 压缩包及许可证。
- 历史倒地起身：`fallAndGetUp3_subject1.bvh`，YY 2026-10-07 的代表性测试明确引用它。另两条通过完整时长和运动复杂度筛选后固定，优先长舞蹈及普通步行。
- GPU：RTX 5080 Laptop 16 GB。不得停止现存其他项目服务。依照真实可用显存选择环境数量与网络配置。
- 当前仓库初始为空且没有远程地址。保存本地 Git 训练快照，不凭空推送到用户未指定的服务。

## 步骤与通过条件

1. 下载/复制相关官方项目、最新分支、LAFAN 说明、许可证及算法论文到 `.reference/`，记录实际 Git 版本和选择依据。保留官方资产来源。
2. 复制所需机器人资产到 `assets/opensprite/`，生成独立训练 MJCF。核对所有 31 个关节顺序、正负轴、惯量、effort/velocity、接触和 PD。CPU 加载、FK 与短物理步必须有限。
3. **按用户再次明确的要求，正式链必须是真正 UMR**：移植 YY 原生 Geno FBX/BVH 蒙皮表面输入、学习点云对应关系、NR surface-vector 优化及其约束。从官方 OpenSprite STL/MJCF 重新构造 Tpose、点云、中心定义和约束，训练全新 Geno→OpenSprite correspondence；禁止使用 X2 的 slots/config/几何/姿态/硬件边界。当前任务空间 IK 仅保留为诊断基线，不作为 UMR 交付。三条动作保留真实时间跨度，不用循环/拼接制造长度；任何重采样、平滑或限速必须记录并验证。
4. 每条导出 root pose、关节位置/速度和身体 FK 数据及原始时长。检查非有限值、位置硬边界、速度、突然跳变、穿地和自碰撞；优先解决明显 retarget 错误，避免 RL 学习不可执行参考。源人体 Hips 与机器人 pelvis 原点不同，retarget 可进行明确记录的绑定偏移和有连续性约束的 root/接触优化，不能为“固定世界高度偏移”的初始假设保留严重穿地。最终转换到训练库后不再偷偷改参考。
5. 用户进一步指定优先复刻本机 `beyondmimic-umr` 的成功 SuperMimic 分支，已定位 `exp/agibot-x2-supermimic-fullbody-joint-2h-20261022@32fc15e`，实际成功训练源码 `1605c558`。直接复制其 plain MLP actor、critic、WM768×3、bf16、buffer/engine/return-adaptive 多动作训练主干，按新机器人31joint/32body及单boxsole适配。采用一个actor/critic/世界模型共享三动作，不沿用先前general teacher64/FSQ架构；参考边界不跨源，最终各动作全长评估。具体采样与MDP优先复刻该已证成功分支，不自行扩大成新研究架构。
6. 独立性检查：复制/隔离本仓库后，在参考目录不可见的条件下加载资产、retarget 短段和训练 smoke。验证真实 GPU step、模型/actor/critic 更新、梯度有限、checkpoint 保存与恢复。
7. 启动单卡正式任务，用户训练预算总计 12 小时，训练 pilot 也计入，不把三条分成三份各 12 小时。先预留必要的完整逐动作评估时间；预算用完停止。若提前达到逐动作验收，可提前结束。
8. 每小时检查进度、GPU/内存、NaN/错误、三动作采样与完成情况、真实与想象模型误差；出现 OOM/崩溃等明确问题，保留日志和 checkpoint，修复后从有效快照恢复，不反复重置预算。连续无改进需检查 retarget/终止/世界模型，不只延长训练。
9. 交付可运行代码、三条源及重定向数据、共享策略完整 checkpoint、逐动作全长定量结果和可视化、确切启动/恢复命令。报告实际训练用时和未达到的指标；不得将 smoke 或局部窗口结果称为完整动作成功。

## 验收方式

工程验收要求参考目录不可用仍可运行，三条 motion 在同一策略中被实际采样，保存/恢复不丢失任务语义。效果验收对每条从头执行至真实结尾，分别报告完成比例、物理失败次数、身体/根部位置与姿态误差、关节限位和子步峰值；评估应关闭训练随机性并保留固定种子，也补充多种子结果。用户指定的成功参考采用相对姿态追踪，其完整起身全局root漂移约0.59m而身体相对误差约0.04m，因此此前团队自行加入的rootXYZ≤0.10m和六核score阈值与该目标不一致，已在正式训练前撤回。采用来源分支同型逐动作完成与误差评估，完整0物理失败是主要目标；位置/姿态/关节/最差片段误差、全局漂移与接触异常如实呈现，不能以平均回报或只播成功片段代替效果。长舞蹈和倒地起身必须分别呈现全程表现。

早期general-teacher原型曾提出缩小位置奖励/失败尺度。正式任务现改为成功参考分支的legacy_full MDP，数值按OpenSprite几何/力矩/速度重新适配并逐项记录，不将原型六核目标强加到另一套已证成功训练逻辑。旧原型checkpoint只作诊断，不能作为正式任务续训。
